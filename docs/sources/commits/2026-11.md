# Commits without an issue: 2026-11

## `FIX - Declare the autocad-mcp server in .mcp.json.`

The user asked on 2026-11-03 that each repo's `.mcp.json` declare the MCP servers its development needs, and to
commit this with no issue link. Reviews were skipped by the user's decision.

**What changed.** `.mcp.json` gained
`"autocad-mcp": { "type": "stdio", "command": ".venv/Scripts/python.exe", "args": ["-m", "autocad_mcp.server"] }`, and
the tracked `.claude/settings.local.json` added `autocad-mcp` to `enabledMcpjsonServers`. The `qmd` entry is unchanged.

**Decisions.**

- The entry is project-level, so it works from any checkout. Rejected: a user-level registration only, because it
  does not reach other machines.
- The path is relative and holds no machine value, because Claude Code starts a project server with the project as
  its working directory. Rejected: an absolute or drive-letter path, for the same reason.
- The server is also listed in the tracked settings file, because that file is what lists this repo's enabled
  servers.

**Limits.** A checkout still needs its `.venv`, which is not tracked ([connect an agent](../../workflows/connect-an-agent.md)).
The Claude Desktop registration through `setup_claude.bat` is unchanged. The entry was checked only as far as the
server answering `tools/list`; that does not show a running AutoCAD is reachable.

## 2026-11-05, maintenance review (no issue)

An overnight maintenance review (run `run_00597272b2d2`, coordinator: the Cemengal architect) left its changes
uncommitted on 2026-11-04/05; the coordinator re-ran its proof on the morning of 2026-11-05, and the user said to
commit them with no issue link.

**What changed, and why.**

- **A1, escape warnings in the tests.** `tests/fake_acad.py` (`f"{self.Path}\\{self.Name}"`) and the docstring of
  `tests/test_setup_prune.py` (`exports\\ `) had invalid escapes: every run printed two `SyntaxWarning`s, and Python
  plans to make them errors. Both strings keep their value (the fake's `FullName` is still `D:\drawings\X-C3D.dwg`).
- **A2, unused names.** `field` (`autocad_mcp/export.py`), the constant `APPROXIMATE_UNITS`
  (`autocad_mcp/export_text.py`) and `FakeApp` in `tests/test_export_jobs.py` and `tests/test_time_budget.py`.
  `format_linear` already returns the "approximate" flag, so the constant was a second copy of that rule that
  nothing read. Found by an AST scan; `git grep` across the repos of `repos.json` and the reviewers found no other use.
- **A3, upstream's tracked bytecode deleted** (`autocad_mcp/__pycache__/__init__.cpython-312.pyc`,
  `server.cpython-312.pyc`): bytecode of upstream's 2025 `server.py`, which the `.venv`'s Python 3.13 never loads.
  Closes [known gap](../../concepts/known-gaps.md) 8.
- **A4, the three old dev logs** (`diag_log.txt`, `live_test_log.txt`, `setup_log.txt`, 2026-10-17/18, ignored) were
  moved out of the repo, to the review's scratch folder under `D:\tmp`, and their four `.gitignore` lines removed.
  Closes known gap 11.
- **A5, wiki drift.** [server](../../modules/server.md) said `delete_entity_by_handle` is bounded to model space; only
  the plural is, and the singular is now known gap 18 (named in the index's "Anything" row).
  [0003](../../decisions/0003-no-writes-under-acc-or-beside-scripts.md)'s "the old logs stay" carries a dated note;
  [overview](../../overview.md) names the four modules instead of "one Python file";
  [test](../../workflows/test.md) gives the suite's ~20 s, not ~5 s. At this ingest,
  [upstream and fork](../../concepts/upstream-and-fork.md) notes that the fork deleted the bytecode.

**Decisions.**

- Committed with no issue link and without the QA and security reviews, by the user's choice on 2026-11-05 (their
  override of root 0034). Rejected: waiting for an issue and the reviews, which the user declined.
- The bytecode is deleted from the tree, not only untracked (`git rm --cached`), because nothing can load it.
  Deleting upstream files is the recorded need of known gap 8, so [0001](../../decisions/0001-minimal-marked-divergence-from-upstream.md)
  is met; there is no line to mark with `# Cemengal`.
- The old logs left the repo rather than staying ignored: root
  [0037](../../../../../docs/decisions/0037-code-follows-the-tables.md) says nothing temporary stays in a repo and
  leftovers are not hidden with `.gitignore`. If one came back, git now shows it as untracked.
- `APPROXIMATE_UNITS` was removed, not wired in: a second copy of `format_linear`'s rule would drift from it. The
  unused names were all in Cemengal-only code.
- 0003's consequence line stays, with a dated note, because a decision record keeps its history.
- Gap 18 is recorded, not fixed: the review changed no tool's behaviour. The fix is P1 below, for the user.
- Kept on purpose: the fake's `Explode`, a tripwire that fails a test if anything explodes an entity.

**Verification.** `pytest`: 196 passed, 1 skipped (`test_prune_reparse.py`: this machine refuses file symlinks
without the privilege) before and after, warnings 2 → 0; again 196 passed, 1 skipped at this ingest. A scratch MCP
stdio client started the edited server as Claude does (`ACAD_AUTOSTART=0`, from `%TEMP%`): 24 tools, 24 unique;

launched. AutoCAD was not run: no change touches COM behaviour. `wiki_lint.py`: 0 errors.

**Proposed and not applied** (the user's decisions):

- **P1** `delete_entity_by_handle`: give it the plural's path (`OwnerID == ModelSpace.ObjectID`, no scan, no `Regen`,
  an error when the delete fails), test-first; known gap 18.
- **P2** colours: `get_color_index` should accept ACI numbers as strings (`create_line(color="1")` draws white while
  `change_entity_color("1")` gives red); drop the three `isdigit` copies; decide what `"black"` (0, ByBlock) means.
- **P3** `create_structure`: drop `"default": "null"` from `color`, `custom_layer` and `label` (an agent sending it gets
  a layer or a text named "null").
- **P4** delete upstream's root `test_script.py`, which draws in the active drawing and is never run (known gap 10).
- **P5** upstream's unused `create_variant_array` and `ensure_structure_layers`: keep upstream's surface or trim it
  (0001, 0004).
- **P6** `README.md`: a banner pointing to `docs/index.md`, or a rewritten tool section (known gap 7).
- **P7** refactor `server.py`'s create methods (~350 lines of near-identical closures) into one helper; upstream code,
  so 0001 applies.
- **P8** `mcp` 2.x (the pin `mcp>=1.2,<2` holds the `.venv` on 1.30.0): a task of its own, with the contract tests
  and a live run.
- **P9** known gaps 5 (`get_entities` unpaged, every entity twice) and 6 (a failed create answers `success` with
